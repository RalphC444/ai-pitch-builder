Basic path vs fast path, rebuilt to make one point

The old version listed nine steps twice, in narrow columns. Steps one to four and the final consult are the same on both paths, so the reader had to compare two lists of tiny text to find the difference. This version shows only what changes: when the client first sees an advisor.

Shared steps collapsedClient, brief, Project Manager and search are one line above. Consult is one line below.
Four steps per path, not nineEach step is a short label and one plain sentence.
The difference is highlighted"Client sees" is step 3 on the basic path and step 1 on the fast path: two steps sooner.
No squeezed textBelow 720px of section width, steps stack as full-width rows. In testing, no line went under 200px.

Two ways to the client

The fast path skips screening. The pitch has to make up for it.

Both paths start the same way and end in a consult. The difference is when the client first sees an advisor.

Both start: client brief → Project Manager → finds advisors

Vetted Basic path
  1. Screeners sentProject questions go out first.
  2. Advisors answerFresh, project-specific answers.
  3. Client sees the listEvery advisor already screened.
  4. Client picksFrom a screened shortlist.
Unvetted Fast path Client sees advisors 2 steps sooner
  1. Client sees the advisorRight away. This is the time saved.
  2. Client picksOn past answers and the profile.
  3. Screeners sentAfterwards, if at all.
  4. Advisor opts inTo a project they already won.

Both end: consult

On the fast path, the pitch is the whole argument. It has past screener answers and a profile, nothing project-specific. That is where the model struggled most, and why it became the case worth solving.

What PMs said: scoring beat reasoning

        
Recommendation reasoning told PMs why an advisor fit, but they still reread every line before sending. A score on each pitch and an underline on each weak statement told them where to look. So the redraw shows B with pitch scoring where the tested concept had reasoning. The A/B result itself (editor first wins) is unchanged.

The beta made pitches fast. The workshop showed why PMs still reread them: the model could be confident and wrong. Version two shows the model's confidence and its sources on every claim, so a PM can see where to look instead of checking everything.

    New section
    
How autonomous should this be?

    

      
      Section copy
      
Level 5 today. A route to 7. A reason to stop there.

      
On a scale where 1 is fully manual and 10 has no person involved, the builder sits at 5: the AI drafts everything and a person reviews all of it. The next step is approving a finished email once. After that, routine follow-ups could send on their own when every compliance check passes. It stops at 7 because no machine can judge whether an email is right for a particular client. A named Project Manager stays accountable for every first email.

    

    
Visual: export the scale and the step cards from the autonomy story. Note the distinction you raised: AI capability is close to 8 because of the companion, but autonomy is 5. Saying both makes the point that trust, not capability, is what's missing.
